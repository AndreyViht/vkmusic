## Откуда приходят обновления

1. `SetupLib/AppUpdater.cs:64` фиксирует источник: владелец `AndreyViht`, репозиторий `vkmusic`.
2. `SetupLib/Services/GitHubClientService.cs:22` через Octokit получает список GitHub Releases: `https://api.github.com/repos/AndreyViht/vkmusic/releases`.
3. Программа сортирует теги по числовой версии, выбирает более новую версию с пакетами и сертификатом.
4. Название, описание, размер и адреса загрузки берутся из данных релиза. Отдельного сервера манифестов обновлений нет.
5. Для обычной распакованной программы выбирается ZIP, для пакетной установки — MSIX (`VK UI3/MainWindow.xaml.cs:939–973`).
6. В Release-сборке проверка запускается при загрузке заголовка окна, также доступна ручная проверка в настройках. Постоянного таймера периодической проверки в исследованном механизме нет.

## Как публикуются

В `.github/workflows/new.yml` описана сборка GitHub Actions для x64. Версия читается из `AppxPackageVersion` основного csproj и подставляется в MSIX manifest. При push в main либо ручном запуске с публикацией создаётся релиз и загружаются ZIP/MSIX/сертификат. Для выпуска новой версии нужно поднять номер версии: при существующем стабильном релизе с тем же тегом шаги публикации файлов пропускаются. Поле ручного запуска `prerelease` фактически не используется — при создании релиза задано `prerelease: false`.

## Найденные проблемы

### 1. Недействующие адреса компонентов — подтверждено сетевой проверкой

Приложение получает HTML вместо FFmpeg ZIP и установщика Runtime. Проверка кода HTTP сама по себе здесь не помогает: сервер отвечает 200. Нужны корректные адреса и проверка формата файла. Это относится к компонентам с `anviht.ru`, а не к файлам обновлений приложения на GitHub.

### 2. Может скачаться пакет чужой архитектуры

`GitHubClientService.FindAssetForArchitecture` сначала ищет архитектуру в имени, а затем выбирает **любой** файл нужного расширения. В актуальных релизах есть только x64. На x86/ARM64 механизм способен выбрать x64 и пометить его как соответствующий ОС. Для x86 это несовместимый пакет; возможность эмуляции на ARM64 не делает такой выбор корректным определением архитектуры.

### 3. Требование сертификата блокирует даже ZIP-релизы

`CheckReleaseForAssets` принимает релиз только при наличии `.cer` в нём или одном из старых релизов. ZIP сам по себе не требует сертификата MSIX. Новый ZIP без доступного сертификата может быть скрыт как неподходящий. У текущих опубликованных релизов сертификаты есть, поэтому сейчас этот дефект не срабатывает.

### 4. Предварительные релизы не фильтруются, обычные SemVer-теги ломают проверку

Нет фильтра `Prerelease`. Числовой prerelease может быть предложен обычному пользователю. Сравнение выполняется через `int.Parse` каждой части тега. Проверен непосредственно извлечённый из исходников `VersionComparer` в изолированном запуске через PowerShell Add-Type:

| Сравнение с 0.3.9.8 | Результат |
| --- | --- |
| `0.3.9.9` | Новее |
| `0.3.10.0` | Новее |
| `v0.3.9.9` | `FormatException` |
| `0.3.9.9-beta` | `FormatException` |

Сейчас опубликованные теги числовые; это дефект совместимости будущих релизов, а не текущий отказ сервера.

### 5. Скачивание не проверяет HTTP-ошибки и требует Content-Length

`FileDownloadService.DownloadFileAsync` не вызывает `EnsureSuccessStatusCode` и сохраняет тело ответа даже при HTTP-ошибке. При подсчёте прогресса используется `ContentLength.Value`, что вызывает исключение при отсутствии заголовка. Нет сверки размера/хеша файла. GitHub API для актуальных assets отдаёт SHA-256 digest, но этот механизм его не использует. Для MSIX остаются проверки Windows при установке; ZIP-ветка не выполняет отдельную проверку подписи/хеша до копирования.

### 6. ZIP-установщик может объявить успех после частичной установки

`InstallationService.GetZipInstallCommand` копирует файлы поверх текущих. Нет резервной копии или отката. `Copy-Item` вызывается без `-ErrorAction Stop`, поэтому многие ошибки не попадают в `catch`; после неудачных попыток записывается лишь предупреждение. Скрипт продолжает работу и выводит «Обновление завершено!». При отсутствии ожидаемого EXE он пытается запустить первый найденный `*.exe`.

Кроме того, внутри скрытого PowerShell-процесса с перенаправленным выводом есть `Read-Host`. Это непригодное ожидание пользовательского ввода для фонового обновления: в зависимости от окружения оно завершится ошибкой либо задержит завершение.

### 7. Установщик Runtime использует неверный способ запуска EXE

`InstallAppRuntimeAsync` скачивает `WindowsAppRuntimeInstall...exe`, а затем передаёт его в `Add-AppxPackage`, предназначенный для пакетов Windows. Даже после восстановления корректной ссылки этот шаг требует исправления способа установки.

### 8. Ошибка обновления может завершить приложение

`VK UI3/Views/UpdatePage.xaml.cs:68–80`: асинхронный обработчик кнопки отключает её и ожидает установку без локального `try/catch/finally`. `DownloadAndOpenFile` повторно выбрасывает исключения. Ошибка скачивания/установки может дойти до глобального обработчика, который завершает приложение; повторная попытка на странице не организована. Отписка от прогресса при выгрузке закомментирована.

### 9. Выбор версии не учитывает требуемый формат заранее

Сервис сначала выбирает самый новый релиз хотя бы с одним форматом. Затем `MainWindow.checkUpdate` проверяет, есть ли нужный ZIP/MSIX, и при отсутствии возвращает `false`. Более старый, но всё ещё новый относительно установленной версии релиз с правильным форматом уже не рассматривается. Пользователь может получить «Обновлений не найдено» при наличии подходящего обновления.

## Уточнение по сессии ВК

После повторного входа библиотека загрузилась. Поиск по исходникам нашёл объявление `TokenChecker.IsTokenValid`, но не его вызовы. Стартовая навигация проверяет количество сохранённых аккаунтов, а ошибки загрузки музыки часто подавляются. Поэтому после отзыва сессии приложение не переводит пользователя на повторный вход. Нужна единая обработка ошибки авторизации ВК, которая остановит запросы, пометит конкретный аккаунт как требующий входа и покажет форму авторизации.

Изменён только отчёт. Исходники обновлятора и настройки системы в ходе проверки не менялись.
